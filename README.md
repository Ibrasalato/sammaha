# سمّها — منصة اقتناء أسماء الشعارات

منصة المنظمة الدولية للإبل لطلب أسماء الشعارات (قعدان وبكار)، ومراجعتها من لجنة الاعتماد، وطرحها في مزاد علني، وإصدار فاتورة إلكترونية للفائز.

## الدورة الكاملة

1. **التسجيل**: مالك الإبل ينشئ حسابًا (الاسم، الجوال، البريد، الهوية اختياري).
2. **طلب شعار**: يختار النوع (قعدان / بكار) ويكتب 3 أسماء. يتم التحقق فورًا:
   - **مطابقة كاملة** مع اسم مسجل أو تحت الطلب أو في مزاد ← الاسم مرفوض ولا يمكن رفع الطلب.
   - **تشابه** (نسبة ≥ 70%) ← مسموح، ويُعرض للجنة للتدقيق.
3. **سداد الضمان**: 50 ريال من المحفظة أو بالبطاقة (ميسّر). يصبح الطلب **تحت المراجعة**.
4. **لجنة الاعتماد**: ترى الأسماء الشبيهة لكل اسم ونسبة التشابه، وتقرر لكل اسم **قبول / رفض**، أو **رفض الطلب كاملًا**، أو **إلغاءه**. الرفض والإلغاء يعيدان الضمان إلى محفظة العميل.
5. **فتح المزاد**: اللجنة تختار الأسماء المقبولة وتحدد موعد البداية والنهاية (توقيت الرياض).
6. **المزاد**: سعر افتتاحي 50 ريال، أقل زيادة 10 ريال، والمزايدة في آخر دقيقتين تمدد المزاد دقيقتين. القعدان باللون الأزرق والبكار باللون العنابي.
7. **الترسية**: يرسو الاسم على أعلى مزايد. إن لم يزايد أحد يرسو على مقدم الطلب بمبلغ الضمان (50 ريال). يُسجَّل الاسم في سجل الأسماء المحجوزة.
8. **الفاتورة الإلكترونية**: فاتورة ضريبية مبسطة مع رمز QR بصيغة هيئة الزكاة (المرحلة الأولى)، تظهر في لوحة المالك ويمكن إرسالها بالبريد عبر n8n.

### إضافات المنصة
- **عرض صور متحرك** في الواجهة الرئيسية (`public/hero/`، والقائمة في `src/components/HeroSlides.tsx`).
- **تقويم الإبل** (`/events`): المهرجانات وسباقات الهجن والأيام العالمية ومزادات سمّها القادمة. المواعيد غير المعلنة رسميًا عليها علامة «موعد متوقع»، وتعدّلها اللجنة من «المواعيد والفعاليات».
- **شهادة تسجيل الاسم** بعد سداد الفاتورة، عليها QR يفتح صفحة **التحقق العامة** (`/verify`).
- **التنبيهات**: تجاوز المزايدة، الترسية، قرار اللجنة، فتح المزاد، استرداد الضمان. في الإنتاج تُرسل أيضًا إلى webhook في n8n (`app_settings.notify_webhook_url`) لواتساب والبريد.
- **صفحات المحتوى**: الأسئلة الشائعة، الشروط والأحكام، الخصوصية، الاسترداد، تواصل معنا. نصوص الشروط والسياسات مسودة تحتاج مراجعة قانونية من المنظمة.
- **تواصل معنا والشكاوى والبلاغات** (`/contact`): شكوى أو بلاغ أو استفسار أو اقتراح، ويحصل مقدّمه فورًا على رقم متابعة `BL-YYNNNN`، ويتابعه برقم الجوال من `/contact/track`. الموظفون يديرونها من «الشكاوى والبلاغات» في لوحة اللجنة (الحالة، الأولوية، المسؤول، رد للعميل أو ملاحظة داخلية)، والمالك المسجّل يراها في «الشكاوى والاستفسارات».
- **البريد عبر n8n** (سير العمل «Sammha 6 — Tickets Email»): تنبيه للفريق عند كل طلب جديد، وتأكيد ورد وتحديث حالة للعميل إن كتب بريده. ضع بريد الفريق وبريد المرسل في عقدة `Settings + Ticket` (`team_email` و `from_email`)، وحتى ذلك الحين تُتجاوز الرسائل.
- **الموظفون والصلاحيات**: مدير النظام الرئيسي هو `ibrasalato@gmail.com` ولا يمكن تخفيض صلاحيته أو إيقافه. من «المستخدمون والصلاحيات» يضيف موظفي لجنة الاعتماد أو مديرين آخرين بكلمة مرور مؤقتة، ويغيّر صلاحياتهم أو يوقف حساباتهم. الموظف يغيّر كلمة المرور من «حسابي».
- **دخول الموظفين خاص** على الرابط `#/ico-staff` ولا يظهر في الموقع. صفحة الدخول العامة لملاك الإبل فقط، وتعطي الرسالة نفسها لأي حساب موظف حتى لا تكشف البوابة.
- **المساعد الذكي** (زر «اسأل سمّها» في كل الصفحات): متصل بسير العمل «Sammha 5 — Website Chat» في n8n (Claude)، يجيب من معلومات المنصة والأسئلة الشائعة والبيانات العامة، ولا يصل إلى سجل الملاك أو الفائزين، ويحوّل الشكاوى إلى صفحة تواصل معنا. الرابط في `VITE_CHAT_WEBHOOK_URL`.
- **العربية والإنجليزية** للصفحات العامة، مع تبديل الاتجاه تلقائيًا. لوحات التحكم بالعربية حاليًا.

### إلغاء الطلب من المالك
- يلغي المالك طلبه من «طلبات الشعارات» قبل المراجعة، أو بعد قبوله ما دام لم يبدأ أي مزاد لأسمائه، ويُعاد الضمان إلى محفظته فورًا مع إشعار.
- تُحذف المزادات المجدولة التي لم تبدأ، وتعود الأسماء متاحة لغيره. بعد بدء أي مزاد لا يمكن الإلغاء.

### قواعد الضمان عند الترسية (افتراضات قابلة للتعديل)
- إن رسا على مقدم الطلب أي اسم من طلبه، يُخصم الضمان من فاتورة أول اسم.
- إن رست كل أسماء الطلب على غيره، يُعاد الضمان إلى محفظته تلقائيًا.

## التشغيل

```bash
npm install
npm run dev
```

بدون إعداد Supabase تعمل المنصة **بنسخة تجريبية كاملة** (البيانات في المتصفح). حسابات تجريبية (كلمة المرور `123456`):

| الدور | الجوال |
|---|---|
| مالك إبل | 0500000001 |
| لجنة الاعتماد | 0500000002 |

## الإنتاج (Supabase)

1. أنشئ مشروع Supabase وفعّل الإضافات `pg_cron` و `pg_net`.
2. نفّذ ملفات `supabase/migrations/` بالترتيب: `0001_schema.sql` ثم `0002_logic.sql` ثم `0003_events_notifications.sql` ثم `0004_owner_photos.sql` ثم `0005_tickets.sql` ثم `0006_staff_roles.sql` ثم `0007_owner_cancel.sql`.
3. انسخ `.env.example` إلى `.env` وضع `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY`.
4. أنشئ حساب مدير النظام من Supabase (Authentication ← Add user) بالبريد `ibrasalato@gmail.com`؛ يصبح `admin` تلقائيًا. وانشر الدالة `admin-create-staff` ليضيف منها حسابات الموظفين من داخل المنصة.
5. الدفع بالبطاقة: انشر الدالتين `create-payment` و `moyasar-webhook` وضع `MOYASAR_SECRET_KEY` و `MOYASAR_WEBHOOK_SECRET`.
6. الفاتورة بالبريد: ضع رابط webhook من n8n في `app_settings.invoice_webhook_url`.
7. بريد الشكاوى: ضع `https://ibrasalato.app.n8n.cloud/webhook/sammha-tickets` في `app_settings.ticket_webhook_url` ورابط الموقع في `app_settings.site_url`.
8. حدّث الرقم الضريبي للمنظمة في `src/lib/config.ts` (`SELLER.vatNumber`).

كل العمليات (الأسعار، الحالات، المحفظة، الترسية) تتم داخل دوال قاعدة البيانات، والجداول مغلقة أمام المتصفح بـ RLS.

## النشر على GitHub Pages

ملف `.github/workflows/deploy.yml` يبني وينشر تلقائيًا عند الدفع إلى `main`. فعّل **Settings → Pages → Source: GitHub Actions**. لتفعيل Supabase في النشر أضف المتغيرين `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` في **Settings → Secrets and variables → Actions → Variables**.

## البنية

```
src/lib/        القواعد المشتركة: المطابقة، الإعدادات، الفاتورة، الواجهة البرمجية
  demoApi.ts    الخلفية التجريبية (نفس منطق SQL)
  supabaseApi.ts الخلفية الحقيقية
src/pages/      الصفحات العامة، لوحة المالك (owner/)، لوحة اللجنة (admin/)
supabase/       قاعدة البيانات ودوال الدفع
```

التقنيات: React + TypeScript + Vite + Tailwind، Supabase (Postgres + Auth)، ميسّر للدفع.
